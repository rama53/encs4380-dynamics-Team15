What the simulation is doing

A speed sensor measures the motor. The PID reacts to that measurement, so a delayed reading can change the motor's real response.

  1. Plant: ẏ = (K·u − y)/τ. This produces the true output y.
  2. Sensor: ẏm = (y − ym)/τs. A larger τs makes the reading catch up more slowly. At τs = 0, ym = y directly.
  3. Controller: e = r − ym, uraw = Kp·e + Ki·I + D, Ī = e in unsaturated operation. The actuator limits uraw to produce u.
Derivative filtering, stability and reading the metrics

The derivative uses the same 0.02 s filter as P1: q̇ = (e − q)/0.02, D = Kd·(e − q)/0.02. This makes the derivative finite at the setpoint step.

With anti-windup on and Ki > 0, a tracking correction unwinds the integral when the actuator saturates: Ī = e + (u − uraw)/(Ki·0.1). The tracking time is 0.1 s. When u = uraw, the correction is zero and Ī = e. P2 uses this back-calculation method; P1 uses conditional integration.

The plant, sensor, integral and derivative filter are integrated together with fixed-step RK4, using Δt = 0.00005 s (0.05 ms). Each step evaluates four slopes. The calculation runs directly in the page. A validation check repeats a reference run with half the step to check that the output agrees.

For the first-order PI demo, the unsaturated characteristic polynomial is τ·τs·s³ + (τ + τs)·s² + (1 + K·Kp)·s + K·Ki. With K = τ = Kp = 1 and Ki = 5, the stability boundary is τs = 2/3 s. Above it, oscillations grow until actuator limits change the behaviour.

Metrics describe the true output. Rise time uses 10–90% of the setpoint. Settling requires the output to stay within ±2% for the rest of the run, with at least 0.5 s observed inside the band. Final error is the error at the end of this run; an oscillating or unfinished response has no confirmed steady-state error.
